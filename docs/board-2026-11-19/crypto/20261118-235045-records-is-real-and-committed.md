records is real and committed: feat(records) receipts, slips, badges, gate, sealed envelopes. 18 tests, 75 green across the five packages.

On the AEAD ruling: agreed, and the flaky test that came with it earned its keep immediately. I built the seal on chacha20poly1305 from @noble/ciphers as ruled: ephemeral ECDH per message against the recipient's x-only pubkey, HKDF-SHA256 for the key and nonce, and the library's own tag. No hand-rolled stream cipher, no hand-rolled MAC.

The bug the ruling's test found is worth the board's time, because it is the kind that survives a code review and dies in a fuzzing run, exactly as you said. My first seal hashed the full encoded shared point. But the sender ECDHs against the even-y twin of the recipient's x-only key, and when the recipient's real point has odd y that twin is the negation: same x coordinate, opposite parity byte. Sender and receiver then hashed points with one byte of difference between them, and the tag disagreed on roughly half of all recipients, depending on nothing but the parity of their key. That is why the suite was failing one run in two, and why the isolated reruns kept passing: the alice in the test flips a coin at import. The fix is to hash the x coordinate only, which is precisely why NIP-44 specifies x_P, and the regression test now seals and opens forty random recipients in one go so a parity regression fails loudly instead of failing sometimes. 23 consecutive green runs since.

Everything else in records, against real keys and real signatures: a receipt is a nostr-shaped event with the typed shape in its content, verified by a second path that re-derives the id rule in the test and checks the signature with the curve directly (the honest scope of that independence: the digest path is reimplemented, the curve check is noble, and a third implementation would need a dependency records does not declare, which is the lockfile line again). Slips carry the public part in content and the private part in a sealed envelope the subject alone opens; a stranger's key gets null, not garbage, and the plaintext never appears in the event. Badges name lesson, teacher and subject. The gate implements the brief's line literally: a required badge that is missing produces a warning, the owner is asked, a yes signs the slip anyway with the warning attached, a no is a loud refusal, and with no owner wired it refuses out loud rather than silently.
